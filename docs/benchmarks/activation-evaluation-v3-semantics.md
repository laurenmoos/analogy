# Activation evaluation v3 semantics

The activation profile owns sampled decoding (`temperature: 0.8`, `top_p: 0.95`). The base configuration is read without modification. Each generation retains its deterministic seed; top-ups use disjoint seeds and can therefore produce additional canonical tactics. Weights remain frozen.

Every structured generation boundary uses the shared prompt runner. Each of the `K` activation candidates is one joint response ordered as analogy, mapping, proof reasoning, predicted state, then tactics. Tactics therefore condition on all preceding proof and analogy information. `prompt_max_attempts` is the total whole-candidate attempt limit, including the initial call. Any nested schema failure retries that complete candidate with the precise diagnostic; provider/runtime failures stop immediately. Retries receive deterministic adjacent seeds in non-overlapping candidate blocks, and artifacts retain every request, raw response, status, diagnostic, and measured token-position cost. Neutral and joint analogy generation use the same retry machinery. The activation profile uses a 90-second model-operation timeout rather than the base profile's shorter interactive timeout.

Validation normalizes semantically equivalent information-flow ordering/duplicates and the two common explicit mapping wrappers (a nested role map or parallel source/proof role arrays). It still rejects undeclared, reversed, incomplete, or ambiguous mappings. Proof-transfer prose may use ordinary grammatical phrases such as “apply the hypothesis,” while command-shaped Lean snippets such as `apply h` remain invalid. Source generation asks for concrete entities/resources that can serve as stable alignment keys rather than generic actor labels. Prompted and shuffled conditions remain historical enum values only; new activation runs compare analogy off (`neutral`) directly with analogy on (`activation_selected`).

Generation exposes `GenerationResult(text, processed_token_positions, diagnostic)` through `generate_with_usage`. The existing `generate` method still returns text. Both backends meter actual input positions at the first decoder block, including chunked prefill and every cached decode step that executes. Invisible special tokens are counted if processed; a predicted final EOS that never enters another forward does not create an invented forward. Text is never decoded and retokenized to reconstruct generation usage. Admission uses the generation encoder's prompt IDs, including its special-token policy, plus the maximum decode allowance. Teacher-forced scoring retains its existing accounting.

Candidate measurement teacher-forces each tactic under the original joint request plus a reconstructed assistant prefix through `predicted_state`; the tactic itself is omitted from that prefix. Selection keeps four independent quantities: proof-state relevance (frozen-embedding cosine similarity), reasoning diversification (the existing whitened activation displacement from neutral), causal utility (patched tactic log-likelihood), and predecessor explanatory value (with/without the previous accepted state). Cross-fitted calibration standardizes these four fields independently. A candidate is selected only when its total score reaches `minimum_selection_score` and its raw causal effect is strictly greater than `minimum_causal_effect`; exact zero therefore abstains under the checked-in defaults.

The selected arm submits the winning joint response's stored tactics directly, with no second selected-tactic generation. The neutral prompt and selected joint response each produce an ordered route, normalized into a state-bound `TacticPlan` and durably frozen before Lean evaluation. Both arms use the same cursor: accepted novel states advance the plan; completion, rejection, repeated state, route exhaustion, or budget exhaustion ends the plan phase. Only then may the same ordinary recovery controller run from the last verified state. Frozen-plan and recovery statuses, progress, calls, verifier results, token positions, and solves are reported separately.

The selected arm's equal-compute ceiling includes joint candidate generation, embeddings, captures, patch scores, and any genuinely new post-selection diagnostic. Recovery can run only when its conservative next-call allowance fits the remaining ceiling. Exhaustion preserves frozen-plan progress but cannot claim a later solve. Equal-tactic recovery retains its fixed Lean cap and separately reported usage. Proof-state embedding diversity remains an observational diagnostic rather than a solve input.

The primary causal outcome is separately reported for selected-arm frozen-plan tactics actually submitted to Lean, including rejections. Because selected tactics come from the measured joint candidate, existing union scores are normally reused. The report gives measured/submitted coverage and keeps this outcome separate from the four-factor candidate selection score. Conventional recovery tactics are outside this causal metric.

Legacy prompted and shuffled generation helpers remain available for old artifacts and isolated generator tests, but they are not active evaluation arms and do not appear in new reports.

Artifact schema v5 deliberately rejects earlier resumes because plan execution, active-arm cardinality, and outcome metrics changed. Start a new run; existing artifacts remain untouched. Within v5, the process lock and bound manifest still govern all writes. Collection records each successful model result, including relevance embeddings with exact processed positions, in an atomic private working checkpoint and each completed cell in a recoverable checkpoint. Resumption checks operation requests and result hashes, reuses durable work, completes collection, and only then freezes calibration, selection, and both state-bound plans. A process death after a model call but before its result is durably published can require repeating that uncommitted call.

Working collection checkpoints temporarily retain vectors because cross-fit calibration is unfinished. Once the frozen checkpoint is published they are removed, and finalization repeats cleanup if publication was interrupted. Default published frozen/trial records retain activation and patch-delta summaries/hashes; full diagnostic vectors require `persist_full_activations`. Each Phase B cell commits four rows (two arms by two budget views) by atomic replacement, so an interrupted commit leaves the prior journal intact. An uncommitted Phase B cell is evaluated again from its frozen selection. Anchor preparation before the manifest is sealed is outside the collection-resume boundary.

Progress per Lean call uses eligible frozen-plan progress divided by eligible plan calls. Recovery calls and total completions remain separate. These changes have unit and fake end-to-end validation; they do not constitute a new real-model experiment or validate an earlier diagnostic smoke run.
